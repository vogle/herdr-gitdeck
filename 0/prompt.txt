## Investigation for the pending PR/MR question (findings so far)
- **Branch PR** (shown in the PR bar and the Review tab): `loadBranchPr` in `src/core/forge/index.ts`.
  - It runs `gh pr view <branch> --repo <repo> --json number,title,state,isDraft,url,reviewDecision,statusCheckRollup` (`prViewArgs`, `src/core/forge/github.ts`) or `glab mr view <branch> --repo <repo> --output json` (`mrViewArgs`, `src/core/forge/gitlab.ts`).
  - So it looks up the PR/MR whose source (head) branch is the current branch. It does not filter by target branch, so a PR into develop or anything else would show too.
  - It only reads `origin`; other remotes such as `glab-base` are not considered.
  - Which one wins when several PRs exist for the same branch (open vs merged) is up to gh/glab and was not verified. gh likely prefers an open one.
  - "No PR" errors matching `NONE` show "No PR/MR for this branch".
- **PR list** (`loadPrs`) lists all PRs/MRs in the repo regardless of target:
  - `gh pr list --repo R --state all --limit 100 --json number,title,state,isDraft,headRefName,headRefOid,author,updatedAt`
  - `glab mr list --repo R --all --per-page 100 --output json`
- **Comparison base** (separate from the PR): the header's "→ main ↓29" and the Review tab's file list compare against a fixed main line.
  - `baseBranch` in `src/core/review.ts` uses `BASES = ["main","master","origin/main","origin/master"]`, and `compareArgs` runs `rev-list --left-right --count base...HEAD`.
  - The PR's actual target branch (baseRefName / target_branch) is not fetched or used.
  - So if an MR targets `develop`, the PR line still shows it, but Review's diff and the ahead/behind counts are measured against main.
  - Likely improvement to offer: fetch `baseRefName` (gh) / `target_branch` (glab) and use it as the Review/compare base when a PR exists.
