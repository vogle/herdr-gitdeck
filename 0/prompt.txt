2. Key Technical Concepts:
   - Herdr mod rules:
     - Code runs in QuickJS: no Node APIs, and no `URL` global.
     - `exec(cmd, args[], {cwd,on,timeout})` takes an argument array (no shell), with a 30 s limit and no stdin.
     - `fs/promises` (`readdir`, `writeFile`) can write under `~/.config/herdr-app`.
     - `image(path)` resolves relative to `~/.config/herdr-app`.
     - Saving any file in a mod folder reloads the mod, except hidden files and folders.
   - Image behavior found by testing:
     - A path drawn while its file is missing is remembered as missing.
     - Overwriting a file in a hidden folder doesn't refresh the screen.
     - So draw only after the download finishes, and save each picture once under a fixed name.
     - The `Avatar` and `AvatarImage` components (from gpui-base) blank the virtual list; use `image(...).w(16).h(16).rounded(8)` instead.
   - `AsyncContext` extends `Context`, so it has `cx.spawn`.
   - Verification flow:
     - `pnpm verify` (typecheck, coverage, build).
     - `pnpm -s dev` (installs into `~/.config/herdr-app/mods/gitdeck`).
     - `herdr-app status` for errors.
     - `herdr-app shot <file>` for screenshots.
     - `herdr-app do gitdeck.tab:history` to switch tabs.
   - Privacy:
     - No Gravatar.
     - Picture files are named by a hash of the email.
     - CLIs run in the home folder (`away`).
     - Downloads are https-only, both direct and on redirect.
