## Answer to give for the current question (draft)
Users cannot get automatic updates through Herdr itself, because Herdr only updates its shipped mods. The options:
- (a) In-mod update check: use fetch or `exec` to read the latest GitHub release or tag, compare it to the current version, and show a `notify()` toast with an "Update" action.
- (b) Self-update via `exec`: download the release `main.js` and `mod.json` and atomically swap `mods/gitdeck`, like `dev-install.sh` does with `herdr-app check`. Hot reload then applies it. Caveats:
  - the 30 s exec limit;
  - network and program-running disclosure;
  - supply-chain trust, so sign or verify the files;
  - user consent;
  - the user may have edited or cloned the mod.
- (c) Publish on herdr.dev/mods with the `herdr-mod` topic and versioned GitHub releases, and let users or their agents re-copy.

Recommendation leaning: notify-and-confirm (a) plus an optional one-click update (b) rather than silent auto-update.
